# Bugbot review guidelines for musicbot

## What this project does

Automates music remix prep: splits songs into stems (Demucs/Lalal.ai),
detects BPM/key/first-kick, trims stems for seamless DAW import, and
rekeys/tempo-matches/mixes stem stacks. Correctness is judged by ear —
regressions are often silent (audio still plays, just slightly wrong).

## Review priorities (highest first)

1. **Unit mismatches in DSP code.** Watch for seconds vs samples vs frames
   vs milliseconds confusion, and values passed between librosa (frames,
   normalized envelopes) and raw numpy (samples, raw amplitudes). A past
   bug: an onset threshold computed in raw envelope units was compared
   against a [0,1]-normalized envelope, silently disabling detection.

2. **Audio shape/layout bugs.** librosa loads (channels, samples);
   soundfile writes (samples, channels). Any transpose, `mono=` flag, or
   `ndim` branch deserves scrutiny. Mono vs stereo paths must both work.

3. **Sample-rate assumptions.** Files arrive at 22.05k/44.1k/48k. Flag any
   hardcoded sample rate or window size in samples that should scale by sr.

4. **Benchmark integrity.** Changes to `tests/benchmark/baseline.json`
   must only accompany genuine detection improvements (look for matching
   algorithm changes in the same PR). Lowering a floor without an
   explanation is a red flag. Fixture clips in `tests/fixtures/` are
   LFS-tracked and regenerated by `musicbot/tools/make_bench_fixtures.py` —
   hand-edited fixtures are suspicious.

5. **Filter stability.** `scipy.signal.butter` in transfer-function (b, a)
   form is numerically unstable at low normalized cutoffs (high order +
   low cutoff/nyquist). Prefer second-order sections (`output='sos'` +
   `sosfiltfilt`) if anyone touches filter code.

6. **Output format contract.** Stems are 24-bit PCM WAV at the source
   sample rate throughout the pipeline. Flag any write that drops
   `subtype="PCM_24"` or resamples implicitly.

## Style

- Don't flag print-based logging — it's intentional in this CLI project.
- Don't demand type-checking or docstring coverage beyond what exists.
- Tests use pytest markers: `unit` (pure logic), `synthetic` (generated
  audio), `benchmark` (real-audio, LFS fixtures, ratchet-gated).
